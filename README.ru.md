# clipshield.nvim — как поставить и пользоваться

Плагин для Neovim, который не даёт секретам попасть в буфер обмена.

Ты держишь список значений, которые не должны никуда уезжать — API-ключи, токены, пароли.
В редакторе они видны как есть, файлы не меняются. Но как только ты копируешь текст **в системный
буфер обмена**, все значения из списка заменяются на заглушки.

При добавлении ты сам говоришь, чем значение должно притворяться. Подменил хостнейм другим
хостнеймом — и логи по-прежнему читаются. Ничего не сказал — будет `REDACTED1`, `REDACTED2`,
с номерами, чтобы два разных секрета не выглядели одинаково.

```
# что ты видишь в редакторе            # что оказалось в буфере обмена
OPENAI_KEY=sk-proj-Ab3xK9zzQq          OPENAI_KEY=REDACTED1
GH_TOKEN=ghp_7fQ2mLwPd                 GH_TOKEN=REDACTED2
error.log  mysite.example              error.log  site1.internal
```

Вставляешь это в чат, в issue, в сообщение коллеге — ключей там нет.

## Важно прочитать до установки

**Выделение мышью в терминале плагин не видит и не маскирует.** Терминал копирует из своего
экранного буфера, Neovim об этом вообще не знает. Плагин работает только тогда, когда ты копируешь
из Neovim клавишами (`y`). Если привык тянуть мышью — он тебе не поможет.

Ещё он намеренно не делает трёх вещей:

- не прячет секреты на экране — они видны всегда;
- не меняет файлы на диске;
- не угадывает секреты по виду. Значение маскируется только потому, что ты сам его добавил.

## Установка

### Вариант 1 — из репозитория (рекомендую)

В конфиг lazy.nvim добавить:

```lua
{ "desire469/Clipshield" }
```

Всё. `setup()` вызывать не нужно, плагин работает сразу после установки.

### Вариант 2 — из архива

Распаковать куда угодно, например в `~/.local/share/clipshield.nvim`, и указать путь:

```lua
{ dir = "~/.local/share/clipshield.nvim" }
```

Минус: обновления придётся забирать руками.

## Как пользоваться

| Клавиши      | Режим      | Что делает                                          |
| ------------ | ---------- | --------------------------------------------------- |
| `<leader>sa` | визуальный | Добавить выделенное, спросит **на что заменять**      |
| `<leader>sA` | визуальный | Добавить с дефолтной заглушкой, ничего не спрашивает  |
| `<leader>sn` | визуальный | Добавить под именем: спросит имя, потом замену        |
| `<leader>sy` | визуальный | Скопировать выделенное **без маскирования**          |
| `<leader>sl` | обычный    | Открыть список обычным буфером                       |
| `<leader>sd` | обычный    | Выбрать запись и удалить                             |
| `<leader>sr` | обычный    | Задать замену существующей записи                   |

То же самое командами: `:ClipshieldAdd`, `:ClipshieldAddDefault`, `:ClipshieldAddNamed`,
`:ClipshieldSetReplacement`, `:YankRaw`, `:ClipshieldList`, `:ClipshieldDelete`.

Обычное копирование (`y`, `yy`, `"+y`) трогать не надо — оно маскируется само.

`<leader>sy` нужен, когда ключ и есть цель: вставить его в браузер, в поле пароля, в другой файл.

## Список секретов

Лежит в `~/.local/share/nvim/clipshield/watchlist.jsonl`, по одной записи на строку.
Строки, начинающиеся с `#`, и пустые игнорируются — можно оставлять себе пометки.

```
# рабочее
{"value":"mysite.example","replacement":"site1.internal","label":"рабочий хост"}
{"value":"sk-proj-Ab3xK9zzQq"}
```

`replacement` — то, чем значение притворяется при копировании. Нет поля — будет заглушка с номером.
`label` — короткое имя записи, под которым она видна в меню `<leader>sd` и `<leader>sr`.
Имя только для меню, в скопированный текст оно никогда не попадает.

Редактируется просто как текст: `<leader>sl` открывает файл обычным буфером, дальше `dd` чтобы
удалить строку, руками дописать чтобы добавить, `:w` чтобы сохранить. Изменения подхватываются
со следующего копирования.

**В этом файле лежат настоящие ключи открытым текстом.** Иначе никак: чтобы найти значение
в копируемом тексте, надо знать, как оно выглядит. Относиться к нему как к любому файлу с секретами.

Совпадение точное, с учётом регистра, в любом месте строки — в том числе внутри URL вида
`https://user:PASSWORD@host`. Запись может занимать несколько строк, так что целый PEM-ключ тоже
работает. Если две записи пересекаются, побеждает длинная — короткая не может разрезать длинный
ключ пополам и оставить хвост в открытом виде. Записи короче 8 символов не принимаются: они
совпадут с половиной твоего кода.

Если строка в файле битая — она пропускается, остальные продолжают работать, а при каждом
копировании прилетает ошибка, пока не починишь. Это единственное, о чём плагин говорит вслух:
молча не защищать — худшее, что он может сделать.

## Настройка

Всё необязательно, это дефолты:

```lua
require("clipshield").setup({
  watchlist = vim.fs.joinpath(vim.fn.stdpath("data"), "clipshield", "watchlist.jsonl"),
  placeholder = "REDACTED",  -- записи без своей замены получают это слово плюс номер
  min_length = 8,         -- короче не добавлять
  keymaps = false,        -- отключить дефолтные маппинги и навесить свои
  prefix = "<leader>s",
})
```

Переписывается только системный буфер обмена (`+`, `*`). Безымянный регистр хранит настоящее
значение, поэтому `yy` и `p` внутри Neovim работают ровно как раньше.
